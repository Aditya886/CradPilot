1. EXECUTIVE OVERVIEW
---------------------
CredPilot is a high-performance, offline-first mobile application built for Android and iOS using React Native (TypeScript). It delivers a unified financial, credit ledger, and operational management ecosystem. Rather than offering a one-size-fits-all interface, CredPilot uniquely reconfigures its UI, navigation flows, and quick-action toolbars based on three specialized App Purpose profiles:
  - Type 1: Local (Personal & Social Ledger — Debts, Trips, and Savings)
  - Type 2: Finance (Financial Planning & Loans — Cash Flow, EMIs, and Savings)
  - Type 3: Tuition (Education & Coaching Hub — Students, Batches, Attendance, Fees)

2. CORE TECHNOLOGY STACK
------------------------
  - Framework: React Native (Bare Workflow 0.74+, TypeScript)
  - Local Database: react-native-quick-sqlite (High-performance JSI SQLite)
  - Local Cache / Session: @react-native-async-storage/async-storage
  - State Management: Redux Toolkit (@reduxjs/toolkit) + React-Redux
  - Networking & Cloud API: RTK Query (createApi, fetchBaseQuery) connecting to Node.js/Express REST APIs
  - Push Notifications: OneSignal Native SDK v5 (react-native-onesignal)
  - UI & Graphics: react-native-svg, react-native-linear-gradient, react-native-popup-menu
  - Navigation: React Navigation (Native Stack + Bottom Tabs + Drawer)
  - Data Interoperability: Custom CSV Tabular Parser & Serializer (exportService, importService)

3. SYSTEM ARCHITECTURE & OFFLINE-FIRST PHILOSOPHY
-------------------------------------------------
CredPilot is engineered with an offline-first foundation:
  - Dual-Database Strategy:
      a) master.db: Handles global auth caching, registered users, and active session pointers.
      b) user_<username>.db: Isolated per-user database dynamically created upon login to store all local transactions, debts, goals, and offline copies of student/loan records.
  - Zero-Latency UI:
      Screens immediately populate from local SQLite tables or Redux cached slices. In the background, RTK Query synchronizes state with the cloud API.
  - Standardized Non-Throwing Mutation Lifecycle:
      Every mutation (API call) follows a strict pattern that avoids swallowing errors:
      ```ts
      const res: any = await someMutationApi(payload);
      if (res?.data?.success || (res?.data && !res?.error)) {
          console.log("res -----", res);
          ShowToast(res?.data?.message || "Success", "success");
          // Update Redux, sync local SQLite, navigate or close modal
      } else {
          console.log("res error -----", res);
          ShowToast(res?.error?.data?.message || res?.data?.message || "An error occurred", "error");
          return;
      }
      ```

4. THE THREE APP PURPOSE PROFILES (TYPES) & WORKFLOWS
-----------------------------------------------------

  TYPE 1: LOCAL (PERSONAL & SOCIAL LEDGER)
  - Purpose: Designed for individuals, roommates, friends, and everyday consumers managing personal bookkeeping.
  - Active Sections on Home / Bottom Nav:
      * Debts & Credit Ledger (Udhar Khata)
      * Plans & Trips Budgeting
      * Savings & Goals
  - Bottom Tab '+' Quick Action Menu:
      * Add Debt Person (Register a contact for borrowing/lending)
      * Record Debt Transaction (Log incoming or outgoing cash)
      * Create Plan / Trip (Initialize a travel or event budget)
      * Add Savings Goal (Create a target milestone)

  TYPE 2: FINANCE (FINANCIAL PLANNING & LOANS)
  - Purpose: Designed for salaried professionals, borrowers, freelancers, and investors managing formal debt obligations.
  - Active Sections on Home / Bottom Nav:
      * Finance Overview & Cash Flow (Income vs Expense)
      * EMI & Loans Tracker
      * Savings & Goals
  - Bottom Tab '+' Quick Action Menu:
      * Add Loan / EMI (Register home, auto, personal, or education loan)
      * Record Loan Payment (Log monthly installment with interest/principal split)
      * Add Savings Goal (Create a financial target)

  TYPE 3: TUITION (EDUCATION & COACHING HUB)
  - Purpose: Designed for independent tutors, private coaching institutes, and teachers managing students and cash collections.
  - Active Sections on Home / Bottom Nav:
      * Tuition Center Dashboard (Collections, Dues, Student count)
      * Students Directory & Statements
      * Batch Scheduler & Teacher Leaves
      * Attendance Roll-Call Register
      * Pending Fees Center
  - Bottom Tab '+' Quick Action Menu:
      * Enroll Student (Name, grade, subjects, batch, parent contact, fees)
      * Create Batch (Title, class range, days, timings)
      * Mark Attendance (Roll call by batch and subjects)
      * Record Fee Payment (Log tuition fee receipt via Cash, UPI, or Bank)

5. CROSS-CUTTING SUBSYSTEMS
---------------------------
  - Authentication: JWT Bearer Token, 6-digit email OTP dispatch and verification, encrypted session persistence, password reset pipeline.
  - Insights Engine: Consolidates metrics across all sections to compute overall Net Worth, Profit/Loss, Cash Inflow vs Outflow, and section-specific graphs.
  - Pro & Subscription Service: Controls feature tiering (Free vs Pro) such as maximum student limits, advanced CSV statement exports, and deep analytics.
  - Dynamic More Drawer: Ensures navigation cleanliness by detecting which section is active on the Home tab and automatically hiding it from the More drawer listing while keeping alternative sections easily accessible.

1. AUTHENTICATION & ONBOARDING SCREENS
--------------------------------------------------------------------------------

1.1 Splash Screen (`src/screens/auth/Splash.tsx`)
  - Purpose: Initial application bootstrapper.
  - UI Elements:
      * CredPilot animated brand logo and typography.
      * Background gradient matching theme palette.
  - Features & Logic:
      * Checks AsyncStorage for existing `user_session` and valid JWT token.
      * Initializes user SQLite database (`switchUserDatabase`).
      * Auto-routes to `BottomTab` if logged in, or redirects to `Slider` (first launch) / `Login`.

1.2 Onboarding Slider (`src/screens/auth/Slider.tsx`)
  - Purpose: Introduces new users to CredPilot's capabilities.
  - UI Elements:
      * 3 swipeable slides highlighting: Debts Ledger, EMI & Loan Tracking, Tuition Management.
      * Dot pagination indicators.
      * 'Get Started' and 'Skip' buttons.
  - Features & Logic:
      * Navigates to `Signup` on completion or `Login` via header link.

1.3 Login Screen (`src/screens/auth/Login.tsx`)
  - Purpose: Returning user authentication.
  - UI Elements:
      * Email input field with regex format validation.
      * Password input field with toggleable show/hide eye icon.
      * 'Forgot Password?' navigation text link.
      * 'Sign In' primary gradient button.
      * 'Don't have an account? Sign Up' bottom footer link.
  - Features & Logic:
      * Invokes `useLoginMutation`. On success, saves JWT token in `AsyncStorage`, populates Redux `authSlice`, initializes isolated SQLite user DB, registers user with OneSignal, and navigates to `BottomTab`.
      * Displays precise backend validation errors via `ShowToast`.

1.4 Sign Up Screen (`src/screens/auth/Signup.tsx`)
  - Purpose: New account creation with Purpose profiling and OTP validation.
  - UI Elements (Two-Step Flow):
      * Step 1:
          - Full Name text input.
          - Email address input.
          - Password & Confirm Password inputs.
          - App Purpose selector cards (3 selectable tiles: Local, Finance, Tuition).
          - 'Continue' button.
      * Step 2 (Verification Modal / State):
          - 6-digit OTP individual input boxes with auto-focus.
          - 45-second countdown timer.
          - 'Resend Code' button (active after timer expires).
          - 'Verify & Create Account' button.
  - Features & Logic:
      * Calls `useSendSignupOtpMutation` on step 1 submission.
      * Calls `useVerifySignupMutation` on step 2 with entered OTP.
      * Upon verification, seeds local database, configures initial purpose, registers session, and logs user in directly.

1.5 Forgot Password Screen (`src/screens/auth/ForgotPassword.tsx`)
  - Purpose: Secure self-service password recovery via email OTP.
  - UI Elements (Three-Step Flow):
      * Step 1: Registered email input + 'Send Reset Code' button.
      * Step 2: 6-digit OTP code entry + 45s resend timer + 'Verify Code' button.
      * Step 3: New Password and Confirm Password inputs + 'Reset Password' button.
  - Features & Logic:
      * Validates inputs, sends verification OTP through `useSendForgotPasswordOtpMutation`, verifies OTP and resets credentials via `useVerifyResetPasswordMutation`.
      * Redirects user back to `Login` upon successful password update.
